To build a next-generation document converter (a low-latency, memorybounded "Pandoc killer") in Zig, you should not choose between mechanical
optimization and advanced mathematics. Instead, you layer them: implement
an E-graph using a Data-Oriented Design (SoA) layout with zero heappointer allocation.
By representing the mathematical congruence closure across flat arrays, you
get the absolute algorithmic minimum for finding optimal document transitions,
powered by bare-metal CPU cache line execution speeds.

1. The Core Architecture
Instead of allocating nodes as independent heap blocks linked via 64-bit
pointers, the entire graph structure is broken down into a set of highly
optimized, parallel arrays ( std.MultiArrayList ).
• Id tracking via u32 indices: Every syntax token, e-node , and e-class is
represented by a plain 32-bit integer.
• The Id Hash Map: An internal hash map tracks structural uniqueness
( OpCode + children arrays) to instantly find existing equivalent terms
without iterating through the tree.
• The In-Place Union-Find Array: A continuous array tracking parent offsets
allows the mathematical Union-Find (Disjoint Set) algorithm to operate over
the document tree in near-constant time ().

pub fn find(self: *FlatEGraph, id: EClassId) EClassId {

4. Memory Allocator Injection Strategy
To achieve low latency, avoid passing standard heap or system allocators to the
execution pipelines. Instead, isolate execution lifetimes within local memory
bounds:
1. std.heap.ArenaAllocator for the Rewrite Loop: Initialize an arena
allocator when starting a file translation loop. All FlatEGraph appends draw
memory sequentially from this pre-allocated buffer.
2. Zero Cleanup Overhead ( Deallocation): When the target file writer
finishes emitting text from the extracted e-graph routes, clear the entire
memory space at once via arena.deinit() . This skips index lookup cycles
and frees memory in a single operational step.

5. Why This Implementation Scales Better Than Legacy
Systems
1. Denser Memory Packing: A traditional Haskell AST layout wastes bytes on
pointer references and structure padding. In this layout, each structural
node requires only 24 bytes of packed memory, fitting millions of syntax
structures comfortably within basic CPU L3 caches.
2. Linear Memory Scans: The compile-time rewriting rules execute via clean
sequential loops over flat arrays ( slice.items(.op) ). This allows the CPU
prefetcher to load elements into registers ahead of time, eliminating the
performance penalties of traditional pointer chasing.
3. Algorithmic Safety: Calling unionClasses links completely different
structural layouts (e.g., changing raw bold text strings into semantic header
variants) without modifying or invalidating the surrounding document tree
context.
